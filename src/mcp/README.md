# mcp

MCP (Model Context Protocol) server exposing the `wombat_tasking` postgres
table to MCP clients, using a local [Ollama](https://ollama.com) `llama3.2`
model to translate natural language questions into read-only SQL.

## Setup

```
cd src/mcp
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Copy `config.yaml` and fill in the `database` credentials (matching a
`wombat_client` role, see [infra/psql/genesis.sh](../../infra/psql/genesis.sh))
and the `ollama` host/model. `config.yaml` is gitignored since it holds
credentials.

Ollama must be running locally with the model pulled:

```
ollama pull llama3.2
```

## Running

```
python server.py config.yaml
```

The server speaks MCP over stdio, so it is intended to be launched by an MCP
client (e.g. an editor or agent), not run standalone.

## Tools

- `list_tasking(active_only, crate_name, host_type)`: direct, parameterized
  lookup of `wombat_tasking` rows.
- `ask_tasking(question)`: natural language question about tasking. The
  question is sent to `llama3.2` to produce a SQL `select` statement, which is
  validated (single statement, `wombat_tasking` only, no write/DDL keywords)
  before being executed. Results are then summarized by `llama3.2`.

All SQL generated by the model is validated in [sql_guard.py](sql_guard.py)
before it touches the database; only `select` statements against
`wombat_tasking` are allowed.
